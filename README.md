# ISPDN protection level calculator (lab work No. 4)

Учебный программный комплекс: описание организации и ИСПДн -> расчёт УЗ-1...УЗ-4 -> подбор мер ->
сравнение с фактическими мерами -> аудит (12 проверок, оценка 0-100) -> план исправлений -> единый отчёт.
Результаты **учебные** и не являются юридическим заключением.

## Запуск

Требуется Python 3.10+ (внешние библиотеки для работы не нужны; для тестов - `pytest`).

```bash
python programs/main_simulator.py все
```

Интерактивный режим: `python programs/main_simulator.py`. Команды:
`все`, `система <номер>`, `сценарий <номер>`, `сценарий импорт <номер ИСПДн>` (формальный акт .txt и .docx),
`эталон` (аудит состояния без трёх внесённых дефектов), `выход`.

```bash
python -m pytest tests -q
```

## Структура

```
data/        исходные данные (единственный источник): организация, системы, матрица УЗ, каталог мер,
             оборудование, справочник СЗИ/СКЗИ, сценарии и тесты
programs/    input_validation, level_calculation, measures_selection, equipment_check, compliance_audit,
             main_simulator (точка сборки) + pipeline, common, scenarios, documents_builder
documents/   реестр, акты, перечень оборудования, план мер, ТЗ, план исправлений, baseline_state, acts/*.docx
reports/     отчёты по уровням, мерам, аудиту, итоговый отчёт, результаты сценариев, таблица тестов
tests/       pytest (39 тестов)
```

Документы и отчёты строятся из тех же данных (реестр не ведётся отдельно). Матрица и каталог
загружаются из `data/level_matrix.py` и `data/measures_catalog.py`, внутри функций не дублируются.

## Что осознанно отброшено из prompt.txt

Шаблон `prompt.txt` общий, а задание лабораторной его частично исключает. Решения:

| Из prompt.txt | Решение | Почему |
|---|---|---|
| PostgreSQL, SQLAlchemy, Alembic | не используются | в задании «данные хранятся в словарях и списках внутри .py»; БД не нужна |
| Dishka, Pydantic, FastAPI | не используются | задание: «достаточно стандартной библиотеки», консольный интерфейс |
| Docker / Compose | не добавлены | нет сервисов и БД; запуск одной командой |
| Groq / LLM | не используется | расчёт уровня и аудит детерминированы; LLM нужен только для извлечения признаков из текста, чего в задании нет |
| Английские имена | применены (по запросу) | имена файлов, переменных, функций и ключей — на английском; термины УЗ, ОТСС, ВТСС, СЗИ, СКЗИ и значения данных остались русскими |

## Допущения и ограничения

1. **Текст лекции в комплект не входил.** Матрица (`data/level_matrix.py`) восстановлена по пп. 9-12 постановления № 1119,
   раскладка мер по уровням (`data/measures_catalog.py`) — учебная; **обе не сверены** с действующими редакциями
   (автоматический поиск официальных текстов не удался). Это отражено в отчёте (раздел 8).
2. **Порог 100 000.** Постановление говорит «менее» и «более» 100 000; ровно 100 000 не покрыто. Принято консервативно:
   100 000 относится к большой группе (`THRESHOLD_IN_LARGE_GROUP`). Порог применяется к каждой ИСПДн отдельно, не к сумме по организации.
3. Для сотрудников порог не применяется (группа «малая» при любом числе).
4. Тип угроз берётся из данных (задан условием) и не выводится из ПО.
5. Приказ № 17: класс ГИС (К1-К3) в данных не задан и не выдумывается — аудит помечает `недостаточно_данных`,
   состав мер приказа № 17 требует ручной сверки.
6. ИБП показан как компонент АРМ (ОТСС в составе АРМ); трактовку нужно сверить с пояснением лекции.
7. Номера сертификатов СЗИ/СКЗИ не указаны (реестры ФСТЭК/ФСБ не запрашивались), наименования средств условные.
8. Удаление ФИО не понижает УЗ автоматически (пример минимизации в `data/measures_catalog.py`).

## Три контрольных дефекта

Внесены в данные (помечены `ДЕФЕКТ` в `data/systems.py` и `data/equipment.py`): заявленный УЗ ИСПДн-03 не совпадает с расчётом,
у ОБ-08 нет классификации ОТСС/ВТСС, у ИСПДн-02 нет меры ЗТС.3. Аудитор находит их общими проверками A04, A07, A08
(без перечня номеров). Правки эталона — `BASELINE_FIXES` в `data/test_scenarios.py`; результат: с дефектами 71/100, эталон 96/100.
